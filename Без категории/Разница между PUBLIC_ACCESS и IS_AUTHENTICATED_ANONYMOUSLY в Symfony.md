## 🔹 **Разница между `PUBLIC_ACCESS` и `IS_AUTHENTICATED_ANONYMOUSLY` в Symfony**

В **Symfony Security** есть два способа разрешить доступ неаутентифицированным пользователям:

- `PUBLIC_ACCESS` (с версии Symfony 5.3)
- `IS_AUTHENTICATED_ANONYMOUSLY`

Они похожи, но имеют **ключевые различия**.

---

## ✅ **1. `PUBLIC_ACCESS` (рекомендуемый способ)**

**Что делает?**

- Полностью отключает систему аутентификации для данного маршрута.
- **Не выполняет** вызов firewall'а и не проверяет пользователей.
- Позволяет Symfony **работать быстрее** и экономить ресурсы.

**Пример использования в `access_control`**:

```yaml
security:
    access_control:
        - { path: ^/public, roles: PUBLIC_ACCESS }
```

🔹 **Когда использовать?**  
✔ Для страниц, где **вообще не нужна аутентификация** (например, публичный API, статичные страницы).  
✔ Когда важна **производительность** (Symfony Security не будет пытаться определить пользователя).

---

## ✅ **2. `IS_AUTHENTICATED_ANONYMOUSLY`**

**Что делает?**

- Включает аутентификацию **даже для анонимных пользователей**.
- Позволяет Symfony **создавать объект пользователя** (`UserInterface`) даже для гостей.
- Гость получает **специальный токен** (`AnonymousToken`).

**Пример использования в `access_control`**:

```yaml
security:
    access_control:
        - { path: ^/guest, roles: IS_AUTHENTICATED_ANONYMOUSLY }
```

🔹 **Когда использовать?**  
✔ Когда **нужен объект пользователя** (например, если у анонимных пользователей есть временные сессии).  
✔ Когда используется **ролевая система** (например, `ROLE_GUEST`).

---

## 🔥 **Главное отличие** 🔥

|Опция|`PUBLIC_ACCESS`|`IS_AUTHENTICATED_ANONYMOUSLY`|
|---|---|---|
|Использует систему аутентификации?|❌ **Нет**|✅ **Да** (анонимный токен)|
|Производительность|🔥 **Быстрее**|🐢 **Медленнее**|
|Создаёт объект пользователя?|❌ Нет|✅ Да (анонимный пользователь)|
|Подходит для публичных API?|✅ **Да**|❌ **Нет**|

---

## 🚀 **Вывод**

- `PUBLIC_ACCESS` **лучше**, если вам просто нужно **открыть доступ** к маршруту.
- `IS_AUTHENTICATED_ANONYMOUSLY` подходит, если вы **используете ролевую систему** или хотите **иметь объект пользователя** даже для гостей.

👉 **Если не знаете, что выбрать – используйте `PUBLIC_ACCESS`!**
